

#### 8.1 Filepaths - Absolute vs Relative

- An absolute file path is a complete reference to the file/directory you want to work with, an absolute path will always refer to the same path no matter where you are in your filesystem tree, it has the complete pathname starting with the root directory `/`
	- e.g: `/home/duznoj/Programming/`

- A relative filepath is an incomplete path which only contains the steps/path needed to get from the current directory to the target file/directory. A relative filepath either starts with the name of the next entity you want to go to, or a `.` which refers to the current directory, or a `..` which refers to the previous/one level up directory.
	- e.g `./include/SDL.h`


- It is best practice to end a path to a directory with an additional `/` at the end of the directory name, Linux commands will work without this as well, but if the directory doesn't exist, then commands will interpret that name as a filename and perform unexpected behaviour.
	- e.g `cp ./file1 ./dir1`, if `dir1` exists AND is a directory, then a copy of `file1` will be placed inside `dir1`, if `dir1` doesn't exist, then a file named `dir1` will be created and it will be copy of `file1`.
	- Instead if we used `cp ./file1 ./dir1/`, now the `cp` command will see if `dir1` is an existing directory, if yes, then will place a copy of `file1` inside `dir1`, else will give an error message saying `dir1` doesn't exist


TL;DR: use `<remaining path>/filename` for files and `<remaining path>/directory/` for directories.


#### 8.2 The `ls` command

Syntax:
```bash
ls [<options>] [<path>]
```

- The `ls` command shows a listing of files and/or directories.
- If `<path>` to a file is given, it only shows the listing of that particular file
- If `<path>` to a directory is given, it shows the listing of all files and directories in the given directory

Some useful options to the `ls` command are:

- `--color=<WHEN>`: emits output with different colors for different types of files and directories
	- The core `ls` command is usually aliased to `ls --color=auto` in the `~/.bashrc` file.
	- See `man ls` for more info on all possible values of `<WHEN>`

- `-l`: Shows a `long` listing, contains much more detail like file permissions, owner, creation date, etc.
- `-a`: Shows ALL files, including hidden files in the `<path>`.
- `-R`: Recursively shows listing of all sub-directories in `<path>`.


#### 8.3 The `cp` command

- This command is used to copy file(s) or director(y|ies) to another place.

Syntax:
```bash
cp [<options>] <source path> <dest path>
# OR
cp [<options>] <source paths list> <dest directory>
```

- When a single source file is to be copied, the destination could be a directory you want to copy the source INTO, or it might be a file path you want the source to be copied and end up as.
	- eg: `cp ~/dir1/file1 ~/dir2/` will result in a file of path `~/dir2/file1` be created which is a copy of `~/dir1/file1`
	- eg: `~/dir1/file1 ~/dir2/file2` will result in a file of path `~/dir2/file2` to be created which is a copy of `~/dir1/file1`

- When copying multiple source files at once, then the destination path MUST be to a directory that all the source files should be copied into.
	- eg: `cp ~/dir1/file1 ~/dir2/file2 ~/dir1/file3 ~/dir4/` will copy all 1st 3 files into `~/dir4/`
- If any of the `<sources>` is a path to a directory, then the `-r | -R` option must be given to recursively copy all files and sub-directories within the source directory.
	- eg:
	  ```bash
	  cp <-r | -R| --recurisve> <source_directory> <dest_directory>
	  ```

- A common pitfall when using the `cp` and `mv` commands is the way the shell interprets paths, this is covered in detail in the end of section 8.1



#### 8.4 The `mv` command

- Used to `move` a file/directory from it's current location to another
- Similar to "cut-paste" of windows
- Also used as a file/directory renaming utility
	- While a separate `rename` utility program does exist, it's syntax is weird so people generally use `mv` to do renaming as well
Syntax:
```bash
mv <source file path> <dest file path>
# OR
mv <source paths list (files and directories)> <dest directory>
```

- Behavior of above 2 commands is similar as that of the `cp` command variants.



#### 8.5 The `rm` command

- Used to delete files and directories
- Items once deleted using `rm` cannot be restored via any Kernel/OS provided mechanisms like Recycle Bins.

Syntax:
```bash
rm [<options>] [<paths to files and directories]
```

Some useful options are:
- `-i`: For interactive deleting, will ask for confirmation before deleting each item.
- `-r`: The `recursive` option, necessary for deleting directories, and all the files and sub-directories withing them.
- `-f`: Forcefully delete things no questions asked. 
- To delete any files whose name begins with a '-' and to not interpret that '-' as a flag, use:
	```bash
	# Filename = -foo
	rm -- -foo
	# OR
	rm ./-foo
	```
