- Implementation is given in [RFC 3174](https://datatracker.ietf.org/doc/html/rfc3174)


Accoring to the RFC:
- All calculations done will be in groups of 32-bit words
- We'll be using bit-wise operations as:
	- `~`: bit-wise NOT
	- `&`: bit-wise AND
	- `|`: bit-wise OR
	- `^`: bit-wise XOR
- Any Addition or subtractions will be done in modular arithmetic of 2<sup>32</sup>

- The bit-shift operations are defined as "circular" shifts:
	- S^n(X) = Circular Left Shift of the word X by n bits
	- In C the bit-shift operations are non-circular, so they discard any bits that go off end
	- eg: 10000101 << 2 == 00010100
	- But Circular Shift is defined as re-wrapping the bits that go off from one end to the other.
	- For above example the Circular Left Shift will be 00010110
	- In C this can be implemented as:
		- S^n(X) = ((X << n) | (X >> (32-n)))



#### Part-1 (Padding):
- SHA-1 processes data in 512-bit blocks
- Basically the entire data is split in 512-bit blocks, SHA-1 is applied to first box, then it's result is somehow combined with the result of the next block and so on

- So the first step is to "pad" our data with somethings to make it's length to be a multiple of 512-bits, even if the ORIGINAL message was of length (512 * n)-bits

- This is done by first taking the original message length, say `l`
- Now append a single `1`-bit, making the length `l+1`
- Now append `m` zero-bits such that in order to get next multiple of 512 you leave bottom 64-bits to encode the length `l` in those last 64-bits
	- i.e `((l+1) + (m) + (64)) % 512 == 0 `
- This is why SHA-1 works on input data whose length < 2<sup>64</sup>. cuz the length of original data needs to be encoded in the last 64-bits after padding.
